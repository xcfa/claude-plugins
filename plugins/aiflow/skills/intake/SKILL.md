Задачи пользователя:

$ARGUMENTS

Ты разбираешь задачи и ставишь их в очередь. Код не читаешь, агентов не запускаешь.

1. Выполни `aiflow doctor --quick`. Если есть строки с ✗ — покажи их и остановись.
2. Если задача неясна настолько, что её нельзя спланировать, задай 1–3 уточняющих
   вопроса одним сообщением и дождись ответа. Иначе не спрашивай.
3. Разбей сообщение на самостоятельные задачи. Каждой дай id: латиница в нижнем
   регистре, цифры, дефисы, до 48 символов. Если одна задача требует результата
   другой, укажи это в `depends_on`.
4. Сложность: `complex`, если задача затрагивает больше 3 файлов, вводит новый
   модуль, меняет схему данных или публичный API, требования неясны или нужен новый
   визуальный язык. Иначе `simple`. Для `simple` ставь `auto_approve_plan: true`,
   только если пользователь не просил смотреть планы.
5. Для задач с интерфейсом заполни `ui`: ссылка на артборд Claude Design, если
   пользователь её дал, иначе `"нет макета"`.
6. Модель и effort исполнителя берутся из настроек по сложности задачи. Добавляй
   `"worker_model"` (`sonnet`, `opus`) или `"worker_effort"` (`low`, `medium`, `high`,
   `xhigh`, `max`), только если пользователь прямо попросил их для этой задачи.
7. Поставь задачи в очередь одной командой:
   ```
   aiflow enqueue <<'JSON'
   [
     {"id": "csv-export", "title": "Экспорт отчётов в CSV", "complexity": "complex",
      "text": "Полный текст задачи из сообщения плюс уточнения", "depends_on": [],
      "auto_approve_plan": false, "ui": null}
   ]
   JSON
   ```
8. Ответь пользователю одной-двумя строками: сколько задач поставлено и какие
   планы он увидит на обсуждение. Монитор уже запущен этим вызовом и сообщит,
   когда планы будут готовы.
