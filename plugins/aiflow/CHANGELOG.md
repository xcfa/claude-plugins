# Изменения aiflow

Здесь — то, что меняет поведение или требует действий при обновлении. Полная история — в `git log`.

Новые настройки служба дописывает в `.aiflow/config.json` сама. Значения, которые были умолчаниями
прежних версий, она не меняет: один раз сообщает о каждом событием в панели, а `aiflow doctor`
перечисляет их при каждом запуске.

## 0.2.109

- **Красная базовая ветка чинится сама.** Когда `master` краснеет после мержа, aiflow перезапускает упавшие
  задания сборки, а если они падают снова — ставит задачу `fix-base-<коммит>` с адресом сборки и концом лога.
  Эта задача идёт несмотря на паузу «ветка красная»; остальные ждут. Настройки: `base_fix` (`auto` или `off`),
  `base_fix_reruns` (сколько раз перезапустить сборку до задачи). Служба допишет их в `.aiflow/config.json` сама.
  Перезапуск сборки расходует минуты GitHub Actions; чтобы оставить только паузу — `"base_fix": "off"`.

## 0.2.108

- **Пауза из-за красной базовой ветки.** Панель больше не предлагает кнопку «Продолжить очередь», когда она
  эту паузу снять не может: кнопка неактивна, рядом написано, что сделать, и стоит ссылка на упавшую сборку.
  `aiflow resume` и событие в ленте тоже говорят, что очередь всё ещё стоит и почему. Сама пауза работает
  как раньше: уходит, когда сборка базовой ветки позеленеет.

## 0.2.107

- **Ревьюер.** Ответ не по форме чинится в той же сессии opencode: aiflow просит её дослать ответ, а не
  начинает ревью заново. Ответ, который отличается только названиями ключей (`findings` вместо `comments`,
  `issue` вместо `text`), принимается. Ответ без списка замечаний по-прежнему не одобрение.
- **Статистика.** Команда `aiflow stats` и раздел в панели: причины ухода задач к человеку, раунды ревью,
  время по стадиям, цена выполненной задачи. Причина пишется кодом в историю задачи (`history[].code`).
- **Защищённые пути.** `**/auth/**` убран из списка по умолчанию: под него попадала папка экрана входа
  во фронтенде. В существующих проектах список не меняется; `aiflow doctor` напомнит о нём.
- **Советы по настройкам.** `aiflow doctor` и событие в панели называют значения, оставшиеся от умолчаний
  прежних версий (`notify: important`, одна `worker_model` на все задачи, `**/auth/**`).
- **CI репозитория.** Тесты в Windows и Linux на Python 3.9 и 3.13, линтер ruff.
- **Код.** `scripts/aiflow.py` разнесён по модулям `scripts/aiflow_*.py` (таблица — в README, раздел «Код»);
  ключи задачи описаны в `aiflow_task.py`. Команды и пути запуска прежние: вход — по-прежнему
  `scripts/aiflow.py`, имена доступны как `aiflow.<имя>`.

При обновлении ничего делать не нужно.

## Переход со старых версий

| Проект создан до | Что изменилось | Что сделать |
| --- | --- | --- |
| 0.2.85 | Папка состояния `runs/` называется `.aiflow/` | Ничего: служба переименует её сама, когда в проекте нет идущих задач |
| 0.2.57 | Модель исполнителя выбирается по сложности задачи | В `.aiflow/config.json` заменить `"worker_model": "sonnet"` на `{"trivial": "haiku", "simple": "sonnet", "complex": "opus"}`, а `worker_effort` — на `{"trivial": "high", "simple": "medium", "complex": "high"}` |
| 0.2.47 | Монитор по умолчанию будит оркестратора только ответом на вопрос | В `.aiflow/config.json` заменить `"notify": "important"` на `"answers"`, если не выбирали `important` сами |
