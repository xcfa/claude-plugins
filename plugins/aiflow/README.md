# aiflow

Плагин Claude Code, который ведёт пачку задач через конвейер «план → реализация →
AI-ревью DeepSeek → мерж в `master`» в фоновых сессиях Claude Code. Вы пишете
задачи одним сообщением оркестратору, обсуждаете планы в PR или в сессии
планировщика, одобряете их — дальше всё идёт само. Очередь, лимиты, порядок ревью
и перезапуски ведёт программа `aiflow`, а не модель: она работает монитором в сессии
оркестратора и сообщает только о том, что требует вашего решения.

## Что внутри

| Компонент | Что делает |
| --- | --- |
| `agents/orchestrator.md` | Интерфейс: принимает задачи, отвечает о состоянии, реагирует на события |
| `agents/planner.md` | Opus/Sonnet: draft PR с планом, доработка плана по замечаниям |
| `agents/worker.md` | Sonnet: реализация по плану, цикл ревью в свою очередь |
| `agents/explorer.md`, `agents/researcher.md` | Haiku: ответы на конкретные вопросы к коду и документации |
| `skills/intake` | `/aiflow:intake <задачи>` — разбор и постановка в очередь, запуск монитора |
| `skills/resume` | `/aiflow:resume` — поднять монитор после перезагрузки |
| `skills/discuss` | `/aiflow:discuss <PR>` — обсудить план в свежей сессии |
| `skills/ui` | `/aiflow:ui` — открыть панель в браузере |
| `monitors/monitors.json` | `aiflow run --events` в сессии оркестратора: поднять службу, события проекта в чат |
| `hooks/hooks.json` | Проверка среды при старте сессии (только в подготовленных репозиториях) |
| `bin/aiflow` | Диспетчер и подкоманды; в PATH Bash-команд сессий |
| `scripts/review.py` | Один раунд ревью: CI-гейт, защищённые пути, DeepSeek, inline-ревью, автомерж |
| `scripts/ui.html` | Панель: что ждёт вас, доска задач по стадиям, события |

## Требования

Claude Code с agent view (`claude agents` открывает полноэкранный список), Python 3.9+,
`git`, `gh` (авторизован), `opencode` с подключённым DeepSeek. Отдельный бот-аккаунт GitHub
нужен только в режиме `review_identity: bot` (см. ниже).

## Установка

```bash
claude plugin marketplace add /путь/к/aiflow-marketplace
claude plugin install aiflow@aiflow-local
```

Если храните маркетплейс в git, закоммитьте исполняемый бит: `git update-index --chmod=+x plugins/aiflow/bin/aiflow`.

## Подготовка репозитория (один раз)

1. **Чей аккаунт.** По умолчанию (`review_identity: self`) ревью и мерж идут от вашего `gh`:
   ревью публикуется комментарием (одобрить свой PR GitHub не даёт), мержит `review.py`
   после вердикта approve и зелёного CI. Если нужна жёсткая граница — GitHub сам требует
   одобрение, — поставьте `review_identity: bot` и заведите бота: fine-grained token на
   репозиторий (Contents, Pull requests, Issues — read/write) в `~/.config/ai-review/token`
   или в `REVIEW_BOT_TOKEN`.
2. **GitHub.** Промежуточной ветки нет: одобренные PR мержатся сразу в `master`
   (`base_branch` в `runs/config.json`). Settings → General: Allow squash merging.
   Защита `master` — по желанию (в приватных репозиториях на бесплатном плане её нет):
   PR, обязательные проверки из `ci.yml`, «Require branches to be up to date», Allow auto-merge;
   обязательное одобрение — только в режиме `bot`. CODEOWNERS и «Require approval of the most
   recent push» не включайте.
3. **Инициализация.** В сессии Claude Code в корне репозитория: `! aiflow init`. Команда
   создаст `runs/config.json`, шаблоны `.github/workflows/ci.yml`,
   `docs/ARCHITECTURE.md`, добавит права для фоновых сессий в `.claude/settings.json`
   и метки `plan-approved`, `needs-human`, `retry`.
4. **Настройка.** Выберите модель ревьюера в панели («Настройки» внизу страницы) или впишите
   `reviewer_model` в `runs/config.json` (`opencode models deepseek`),
   при желании положите свои инструкции ревьюера в `.opencode/aiflow-reviewer.md` (по умолчанию —
   `templates/reviewer.md` плагина; aiflow запускает его агентом `aiflow-reviewer` через отдельный
   конфиг opencode, так что он не пересекается с агентами проекта),
   заполните `ci.yml`, добавьте в `.claude/settings.json` allow-правила для сборки и тестов
   проекта (иначе фоновые сессии будут ждать вашего разрешения). Закоммитьте всё, кроме `runs/`.
5. **Доверие к папке.** Хотя бы раз откройте `claude` в репозитории интерактивно и примите
   доверие — иначе фоновые сессии не стартуют.
6. **Проверка.** `! aiflow doctor`.

Чтобы вызывать `aiflow` из обычного терминала, добавьте в PATH каталог `bin` плагина
(путь показывает `claude plugin list`, строка «Read from»).

## Работа

1. Откройте сессию оркестратора (очередь ведёт служба aiflow, так что закреплять сессию
   не обязательно; закреплённая не засыпает и сразу пересказывает события):
   ```bash
   claude --bg --agent aiflow:orchestrator --name aiflow "Готов к задачам"
   claude agents     # выделите строку aiflow, Ctrl+T, затем Enter
   ```
2. В этой сессии: `/aiflow:intake 1) экспорт отчётов в CSV 2) починить пагинацию в API …`
3. Монитор сообщит, когда планы будут готовы. Обсуждайте план в PR (комментарием —
   планировщик проснётся сам), в сессии планировщика (`claude attach <id>`) или через
   `/aiflow:discuss <PR>`. Одобрение — метка `plan-approved`, кнопка в панели
   или `! aiflow approve <id>`.
4. Реализация и ревью идут без вас. PR с общими файлами ревьюятся по одному, с rebase на
   свежий `master`; одновременно — только PR без общих файлов (`review_concurrency`). Мерж всегда
   по одному и только из ветки, которая не отстаёт от `master`.
5. При «нужен человек» оркестратор объяснит причину. Повтор — `aiflow retry <id>`,
   метка `retry` или кнопка в панели. Повтор сначала возобновляет ту же сессию (с её контекстом
   и незакоммиченными правками) в той же стадии; новая сессия запускается, только если возобновить
   не удалось. Можно и ответить самой сессии (дать доступ, «всё норм»): когда она снова
   заработает или пришлёт отчёт, монитор сам вернёт задачу в её стадию.
6. Одобренные PR с зелёным CI сами уходят squash-мержем в `master`. Проверьте `master`
   после мержей; найденное — новой пачкой через `/aiflow:intake` или `git revert`.

### Служба и несколько проектов

Очереди ведёт служба aiflow: один фоновый процесс на пользователя для всех проектов из
`~/.aiflow/projects.json`. От сессий Claude она не зависит: закрытие сессии оркестратора её
не останавливает. Проект попадает в службу при `aiflow init` или `aiflow up` в его каталоге;
монитор сессии оркестратора (`/aiflow:intake`, `/aiflow:resume`) сам поднимает службу, если её нет,
и перезапускает её, если она старше установленной версии плагина, а сам только пересказывает
события своего проекта в чат.

```bash
aiflow up               # запустить службу и добавить в неё текущий проект
aiflow up --autostart   # и запускать службу при входе в систему (--no-autostart — выключить)
aiflow projects         # проекты службы, её версия и адрес панели
aiflow forget [путь]    # убрать проект из службы (задачи и PR не трогаются)
aiflow down             # остановить службу; фоновые сессии Claude продолжат работать
```

После перезагрузки машины с автозапуском ничего делать не нужно; без него — `aiflow up`
или `/aiflow:resume` в сессии оркестратора. В сессии, продолженной через `claude --resume`,
Claude Code монитор плагина повторно не запускает: `/aiflow:resume` запускает его инструментом
Monitor, и уведомления в чат приходят первые 30 минут; служба при этом работает без ограничений.
Автозапуск берёт самую новую установленную версию плагина из того же маркетплейса. `aiflow down`
останавливает службу, пока вы сами не запустите её снова: мониторы сессий её не поднимают. Порт общей панели — `ui_port`
в `~/.aiflow/config.json` (8765 по умолчанию, `0` — без панели).
Сессии, которые остановились или пропали (перезагрузка, закрытие), монитор возобновляет сам —
один раз подряд (`auto_resume` в `runs/config.json`, `0` — выключить); если сессия снова
останавливается без продвижения, задача уходит в «нужен человек». Сессию, остановленную вами
намеренно, монитор тоже поднимет: чтобы задача не продолжалась, поставьте очередь на паузу
или закройте PR.

Монитор пишет оркестратору (и тем самым будит его) только о том, что ждёт вас: план готов
или обновлён, сессия ждёт ответа, нужен человек, смержено, задача снята (тогда оркестратор
закрывает свой вопрос по ней), пауза и её снятие, ошибки, пачка завершена. Остальные события видны в панели. Настройка `notify` в `runs/config.json`:
`important` (по умолчанию), `all` — все события, `none` — ничего, только панель.

Те же важные события, кроме снятия задачи, монитор показывает системными уведомлениями (Windows, macOS, Linux
с `notify-send`), так что о них вы узнаете и без чата и панели. Выключить — `desktop_notify: false`.

## Панель

Её держит служба: `http://127.0.0.1:8765/`. `aiflow ui --open --detach` (или `/aiflow:ui`) поднимает
службу, если нужно, и открывает панель отдельным окном (режим приложения Edge или Chrome, иначе
вкладка браузера). Панель слушает только loopback, действия защищены токеном страницы.
Сверху — что ждёт вас во всех проектах (у «нужен человек» — причина и строка «Что сделать»; одобрить план, повторить, открыть сессию — кнопка
открывает `claude attach`; в Windows Terminal — вкладкой общего окна `aiflow` с названием задачи в заголовке), ниже — проекты, у каждого кнопка «Дать задачу» (открывает чат с координатором проекта во вкладке терминала с именем проекта; если координатора нет — запускает его), своя пауза
и доска задач по стадиям (под названием задачи на ревью написано, чем оно занято: ждёт запуска CI, ждёт CI и сколько проверок прошло, работает ревьюер opencode (что он сейчас читает или запускает, какой шаг, сколько токенов), идёт мерж или исполнитель правит код; ссылка «Ревьюер» в строке задачи открывает сессию ревьюера в терминале (`opencode -s <id>`); клик по названию задачи открывает её сессию в терминале, «Снять» останавливает её сессии и закрывает PR), расход токенов по проектам, задачам и моделям (вход, выход, чтение и запись кэша, вместе с сабагентами и ревьюером opencode — его расход и цену сообщает сам opencode) с итогом по проекту и оценкой цены по тарифам API — проект в этой таблице сворачивается до одной строки; свои тарифы задаются в `prices` в `~/.aiflow/config.json` и лента событий. В разделе «Настройки» выбирается
модель ревьюера opencode для выбранного проекта из списка `opencode models` (или вписывается вручную как `provider/model`).
Значение пишется в `reviewer_model` в `runs/config.json` и действует со следующего раунда ревью.

### В Claude Desktop

`aiflow init` добавляет в `.claude/launch.json` две конфигурации для Browser pane вкладки Code:
`aiflow` подключается к панели службы, а `aiflow (запустить службу)` запускает службу
на переднем плане. Откройте сессию в папке репозитория, в выпадающем списке серверов на панели сессии выберите
нужную конфигурацию (или откройте Browser pane: Ctrl+Shift+B / Cmd+Shift+B) и закрепите панель
рядом с чатом. Вторая конфигурация содержит пути вашей машины: после обновления плагина
перезапустите `aiflow init`, а в общий репозиторий этот файл лучше не коммитить. Если в
`launch.json` есть комментарии, init его не трогает — добавьте записи вручную по образцу из
`aiflow init` в чистом репозитории.

Остановить службу вместе с панелью — `aiflow down` (продолжить — `aiflow up`). Пауза очереди (`aiflow pause` или кнопка в панели) не трогает работающие
сессии, только не даёт стартовать новым. Сами фоновые сессии останавливаются в `claude agents` (`Ctrl+X`)
или `claude stop <id>`.

Строка состояния в Claude Code (`~/.claude/settings.json`):

```json
{ "statusLine": { "type": "command", "command": "python3 /путь/к/плагину/scripts/aiflow.py statusline" } }
```

## Команды

| Команда | Назначение |
| --- | --- |
| `aiflow init` / `doctor` | Подготовить репозиторий / проверить среду |
| `aiflow status [--json]` | Состояние очереди |
| `aiflow approve <id>` | Одобрить план |
| `aiflow retry <id>` | Повторить задачу в `needs_human` |
| `aiflow allow-path <id> <glob>…` | Разрешить задаче защищённые пути (только человек; задача в «нужен человек» продолжит работу) |
| `aiflow amend <id> <текст>` / `--file F` | Дополнить идущую задачу: правку получит её текущая сессия (планировщик или исполнитель, даже посреди работы — через хук); в панели — кнопка «Дополнить». Обычный комментарий в PR после начала реализации работает так же |
| `aiflow cancel <id>… [--keep-pr]` | Снять задачи на любой стадии: остановить их сессии, закрыть PR (ветка остаётся); в панели — кнопка «Снять» |
| `aiflow pause [причина]` / `resume` | Пауза очереди |
| `aiflow up [--open] [--autostart\|--no-autostart]` | Запустить службу, добавить в неё текущий проект |
| `aiflow down [--no-autostart]` / `aiflow stop` | Остановить службу и панель |
| `aiflow projects` / `forget [путь]` | Проекты службы / убрать проект |
| `aiflow ui [--open] [--detach]` | Открыть панель (окном приложения с `--open`) |
| `aiflow tick` | Один проход вручную |
| `aiflow enqueue` | Поставить задачи (JSON со stdin; использует intake) |
| `aiflow report`, `review`, `reply` | Команды для агентов |

## Как это устроено

Состояния задачи: `new → planning → plan_review → approved → in_progress → ready → in_review → merged`,
плюс `needs_human` и `cancelled` (`approved` — план одобрен, задача ждёт слот исполнителя). Каждый переход — проверяемый сигнал: отчёт сессии
(`aiflow report`), метка PR, состояние сессии из `claude agents --json`, статус PR.
`concurrency` ограничивает сессии планирования и реализации; ревью идёт поверх лимита:
до `review_concurrency` PR сразу, если у них нет общих файлов. Rate limit ставит очередь на паузу на
`rate_limit_pause_minutes`, красный `master` после мержа — до починки. Причины паузы независимы,
и пауза останавливает не только запуск сессий, но и мерж.

Ревью fail-closed: неизвестная серьёзность замечания считается блокирующей, обрезанный дифф
без подтверждения ревьюера блокирует, изменения защищённых путей блокируются без вызова
модели. Красный CI возвращается worker'у до ревью и раунд не тратит (не больше `max_ci_fixes` раз подряд).
Отсутствие проверок CI при наличии workflow — ошибка, а не «прошло». Задача без плана ограничена
по размеру изменения (`direct_max_files`, `direct_max_lines`). Отчёты сессий проверяются: PR должен
быть открыт из ветки `ai/<id>`.

## Тесты

```bash
python -m unittest discover -s plugins/aiflow/tests
```

Тесты гоняют очередь (`Dispatcher`) и раунд ревью (`review.py`) на подделках `claude` и `gh`:
ни сеть, ни модели не нужны.

## Что проверить при первом запуске

- Монитор стартует в фоновой сессии оркестратора по первому `/aiflow:intake`: в сессии
  появится строка `[aiflow] монитор запущен; панель: …`. Мониторы плагинов работают только
  в интерактивных сессиях; фоновая сессия интерактивная, но это главное, что надо увидеть
  своими глазами.
- Тестовая задача проходит путь до `ready` без зависаний на запросах разрешений.
- AI-ревью появляется в PR, после approve PR мержится в `master`.

## Ограничения

- Agent view в research preview; при смене флагов CLI правки нужны в классе `Claude` в `scripts/aiflow.py`.
- Фоновые сессии локальные: выключение машины их останавливает; после `/aiflow:resume` монитор их возобновит.
- Deny-правила защищают от случайностей, а не от злого умысла. В режиме `self` агенты работают
  с вашим `gh`, и смержить в обход ревью им мешают только deny-правила (`gh pr merge`, `gh api`)
  и инструкции; жёсткая граница — режим `bot` с обязательным одобрением в защите ветки.
- На Windows монитор запускает `bin/aiflow` через ту же оболочку, что и Claude Code (Git Bash);
  из PowerShell используйте `bin/aiflow.cmd`.
