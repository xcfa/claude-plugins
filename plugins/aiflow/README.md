# aiflow

Плагин Claude Code, который ведёт пачку задач через конвейер «план → реализация →
AI-ревью DeepSeek → мерж в `master`» в фоновых сессиях Claude Code. Вы пишете
задачи одним сообщением оркестратору, обсуждаете планы в PR или в сессии
планировщика, одобряете их — дальше всё идёт само. Очередь, лимиты, порядок ревью
и перезапуски ведёт программа `aiflow`, а не модель: она работает монитором в сессии
оркестратора и сообщает только о том, что требует вашего решения.

## Что внутри

| Компонент | Что делает |
| --- | --- |
| `agents/orchestrator.md` | Интерфейс: принимает задачи, отвечает о состоянии, реагирует на события |
| `agents/planner.md` | Opus/Sonnet: draft PR с планом, доработка плана по замечаниям |
| `agents/worker.md` | Sonnet: реализация по плану, цикл ревью в свою очередь |
| `agents/explorer.md`, `agents/researcher.md` | Haiku: ответы на конкретные вопросы к коду и документации |
| `skills/intake` | `/aiflow:intake <задачи>` — разбор и постановка в очередь, запуск монитора |
| `skills/resume` | `/aiflow:resume` — поднять монитор после перезагрузки |
| `skills/discuss` | `/aiflow:discuss <PR>` — обсудить план в свежей сессии |
| `skills/ui` | `/aiflow:ui` — открыть панель в браузере |
| `monitors/monitors.json` | `aiflow run --events` в сессии оркестратора |
| `hooks/hooks.json` | Проверка среды при старте сессии (только в подготовленных репозиториях) |
| `bin/aiflow` | Диспетчер и подкоманды; в PATH Bash-команд сессий |
| `scripts/review.py` | Один раунд ревью: CI-гейт, защищённые пути, DeepSeek, inline-ревью, автомерж |
| `scripts/ui.html` | Панель: что ждёт вас, доска задач по стадиям, события |

## Требования

Claude Code с agent view (`claude agents` открывает полноэкранный список), Python 3.9+,
`git`, `gh` (авторизован), `opencode` с подключённым DeepSeek, отдельный бот-аккаунт
GitHub с правами Write на репозиторий.

## Установка

```bash
claude plugin marketplace add /путь/к/aiflow-marketplace
claude plugin install aiflow@aiflow-local
```

Если храните маркетплейс в git, закоммитьте исполняемый бит: `git update-index --chmod=+x plugins/aiflow/bin/aiflow`.

## Подготовка репозитория (один раз)

1. **Бот и токен.** Fine-grained token бота на этот репозиторий: Contents, Pull requests,
   Issues — read/write. Положите в `~/.config/ai-review/token` или в `REVIEW_BOT_TOKEN`.
2. **GitHub.** Промежуточной ветки нет: одобренные PR мержатся сразу в `master`
   (`base_branch` в `runs/config.json`). Settings → General: Allow auto-merge,
   Allow squash merging. Защита `master`: PR, 1 approval, обязательные проверки из
   `ci.yml`, «Require branches to be up to date». Не включайте CODEOWNERS и «Require approval
   of the most recent push» для `master`: одобрение бота их не удовлетворит.
3. **Инициализация.** В сессии Claude Code в корне репозитория: `! aiflow init`. Команда
   создаст `runs/config.json`, шаблоны `.opencode/agent/reviewer.md`, `.github/workflows/ci.yml`,
   `docs/ARCHITECTURE.md`, добавит права для фоновых сессий в `.claude/settings.json`
   и метки `plan-approved`, `needs-human`, `retry`.
4. **Настройка.** Выберите модель ревьюера в панели («Настройки» внизу страницы) или впишите
   `reviewer_model` в `runs/config.json` (`opencode models deepseek`),
   заполните `ci.yml`, добавьте в `.claude/settings.json` allow-правила для сборки и тестов
   проекта (иначе фоновые сессии будут ждать вашего разрешения). Закоммитьте всё, кроме `runs/`.
5. **Доверие к папке.** Хотя бы раз откройте `claude` в репозитории интерактивно и примите
   доверие — иначе фоновые сессии не стартуют.
6. **Проверка.** `! aiflow doctor`.

Чтобы вызывать `aiflow` из обычного терминала, добавьте в PATH каталог `bin` плагина
(путь показывает `claude plugin list`, строка «Read from»).

## Работа

1. Откройте сессию оркестратора и закрепите её, чтобы монитор не останавливался в простое:
   ```bash
   claude --bg --agent aiflow:orchestrator --name aiflow "Готов к задачам"
   claude agents     # выделите строку aiflow, Ctrl+T, затем Enter
   ```
2. В этой сессии: `/aiflow:intake 1) экспорт отчётов в CSV 2) починить пагинацию в API …`
3. Монитор сообщит, когда планы будут готовы. Обсуждайте план в PR (комментарием —
   планировщик проснётся сам), в сессии планировщика (`claude attach <id>`) или через
   `/aiflow:discuss <PR>`. Одобрение — метка `plan-approved`, кнопка в панели
   или `! aiflow approve <id>`.
4. Реализация и ревью идут без вас. PR ревьюятся строго по одному: следующий встаёт
   на ревью только после мержа предыдущего, с rebase на свежий `master`.
5. При «нужен человек» оркестратор объяснит причину. Повтор — `aiflow retry <id>`,
   метка `retry` или кнопка в панели.
6. Одобренные PR с зелёным CI сами уходят squash-мержем в `master`. Проверьте `master`
   после мержей; найденное — новой пачкой через `/aiflow:intake` или `git revert`.

После перезагрузки машины: подключитесь к сессии оркестратора и выполните `/aiflow:resume`.

## Панель

Монитор поднимает её сам: `http://127.0.0.1:8765/` (порт — `ui_port` в `runs/config.json`,
`0` — выключить). Без монитора: `aiflow ui --open`. Панель слушает только loopback,
действия защищены токеном страницы. Сверху — что ждёт вас (одобрить план, повторить,
открыть сессию), ниже — доска задач по стадиям и лента событий. В разделе «Настройки» выбирается
модель ревьюера opencode из списка `opencode models` (или вписывается вручную как `provider/model`).
Значение пишется в `reviewer_model` в `runs/config.json` и действует со следующего раунда ревью.

### В Claude Desktop

`aiflow init` добавляет в `.claude/launch.json` две конфигурации для Browser pane вкладки Code:
`aiflow` подключается к панели, которую поднял монитор, а `aiflow (без монитора)` запускает панель
сама. Откройте сессию в папке репозитория, в выпадающем списке серверов на панели сессии выберите
нужную конфигурацию (или откройте Browser pane: Ctrl+Shift+B / Cmd+Shift+B) и закрепите панель
рядом с чатом. Вторая конфигурация содержит пути вашей машины: после обновления плагина
перезапустите `aiflow init`, а в общий репозиторий этот файл лучше не коммитить. Если в
`launch.json` есть комментарии, init его не трогает — добавьте записи вручную по образцу из
`aiflow init` в чистом репозитории.

Остановить: отдельно запущенную панель — `aiflow ui --stop`, монитор вместе с панелью — `aiflow stop`
(продолжить — `/aiflow:resume`). Пауза очереди (`aiflow pause` или кнопка в панели) не трогает работающие
сессии, только не даёт стартовать новым. Сами фоновые сессии останавливаются в `claude agents` (`Ctrl+X`)
или `claude stop <id>`.

Строка состояния в Claude Code (`~/.claude/settings.json`):

```json
{ "statusLine": { "type": "command", "command": "python3 /путь/к/плагину/scripts/aiflow.py statusline" } }
```

## Команды

| Команда | Назначение |
| --- | --- |
| `aiflow init` / `doctor` | Подготовить репозиторий / проверить среду |
| `aiflow status [--json]` | Состояние очереди |
| `aiflow approve <id>` | Одобрить план |
| `aiflow retry <id>` | Повторить задачу в `needs_human` |
| `aiflow pause [причина]` / `resume` | Пауза очереди |
| `aiflow ui [--open] [--detach] [--stop]` | Панель |
| `aiflow stop` | Остановить монитор и панель |
| `aiflow tick` | Один проход вручную |
| `aiflow enqueue` | Поставить задачи (JSON со stdin; использует intake) |
| `aiflow report`, `review`, `reply` | Команды для агентов |

## Как это устроено

Состояния задачи: `new → planning → plan_review → in_progress → ready → in_review → merged`,
плюс `needs_human` и `cancelled`. Каждый переход — проверяемый сигнал: отчёт сессии
(`aiflow report`), метка PR, состояние сессии из `claude agents --json`, статус PR.
`concurrency` ограничивает сессии планирования и реализации; ревью идёт поверх лимита,
но строго по одному PR (`review_lock`). Rate limit ставит очередь на паузу на
`rate_limit_pause_minutes`, красный `master` после мержа — до починки.

Ревью fail-closed: неизвестная серьёзность замечания считается блокирующей, обрезанный дифф
без подтверждения ревьюера блокирует, изменения защищённых путей блокируются без вызова
модели. Красный CI возвращается worker'у до ревью и раунд не тратит.

## Что проверить при первом запуске

- Монитор стартует в фоновой сессии оркестратора по первому `/aiflow:intake`: в сессии
  появится строка `[aiflow] монитор запущен; панель: …`. Мониторы плагинов работают только
  в интерактивных сессиях; фоновая сессия интерактивная, но это главное, что надо увидеть
  своими глазами.
- Тестовая задача проходит путь до `ready` без зависаний на запросах разрешений.
- Бот одобряет PR, автомерж включается.

## Ограничения

- Agent view в research preview; при смене флагов CLI правки нужны в классе `Claude` в `scripts/aiflow.py`.
- Фоновые сессии локальные: выключение машины их останавливает (`/aiflow:resume`, затем `aiflow retry`).
- Deny-правила защищают от случайностей, а не от злого умысла; реальная граница — права токена бота.
- На Windows монитор запускает `bin/aiflow` через ту же оболочку, что и Claude Code (Git Bash);
  из PowerShell используйте `bin/aiflow.cmd`.
